# GCT USB4105 footprint

`examples/footprints/USB4105.tsx` authors `USB-C_Receptacle_GCT_USB4105` through the absolute-positioned JSX API. `examples/parts/USB4105GFA.ts` binds the USB4105-GF-A component to that declaration; `examples/basic.tsx` resolves it during board compilation. Inspect it with `bun run footprints:inspect`, then open `/tmp/react-pcb-footprints/index.html` and toggle the layers.

## Coordinate convention

All values below are mm, viewed from the component side. Origin is the center of the nominal 8.94 × 7.35 mm shell body. +x points right; +y points toward the mating opening. The recommended PCB edge is y = +3.675. That edge is a documentation graphic, not an enforced board-outline constraint; a board placement must align it with the intended edge separately. Back placement uses the standard footprint reflection and semantic-layer swapping.

The root box spans x = -5.32…+5.32, y = -4.76…+4.18 (the courtyard centerline). Containers contribute no physical geometry. Fixed offsets resolve all feature centers in exact integer nanometres.

The composite IDs label physical shared lands, not slash-separated references or two overlaid geometric pads. The KiCad reference instead uses coincident pads with separate A/B contact labels for the four shared lands. Normalizing each shared land to one IR entity avoids duplicated manufacturing geometry. All contacts remain accounted for in the component's logical-pin mapping.

SMT pads are rectangular, following the manufacturer's recommended solder-area drawing. KiCad uses rounded rectangles with a 0.25 corner ratio; that optional corner treatment is not copied. Copper, mask and paste footprints use the nominal land envelope, matching the reference's default aperture approach. Explicit mask expansion, paste reduction, and stencil tuning require a separate manufacturing profile; current board mask expansion metadata is not applied by the footprint compiler.

## Core support added for this footprint

Physical footprint schema version **2** adds optional `drill.slot: [width, height]`. `diameter` is retained as the slot tool diameter and must equal the minor dimension. The dimensions must be positive and unequal, fit the feature envelope, and obey exact-number limits. The slot follows the containing feature's rotation. Round-drill JSON remains unchanged, and version-one round-drill physical footprints remain readable. A version-one footprint containing a slot fails explicitly.

New compilations emit physical version two. The authoring declaration protocol remains version one and board IR remains version two; those version namespaces are independent. The compatibility pad index carries millimetre `slot` dimensions as well as diameter, so it does not silently collapse a slot to a circular drill. Manufacturing consumers still use authoritative physical geometry and must check its schema version. SVG projects slots as capsule primitives with `data-drill-shape="slot"`.

Regression tests independently assert all manufacturer contact centers/sizes, mounting/locating geometry, pin-map coverage, layer resolution, transformations, serialization, deterministic SVG output, legacy round-drill support, and invalid slot rejection. Broader manufacturing checks remain a later plan phase.
